Order Manager

The slot's order clerk. It builds every order, sends each to the Gateway exactly once, and follows it from submission to a closed status — so the slot can always ask which orders are its own, which are still working, and how much each has filled.

v3 draft, 2026-11-06 — not agreed. Behaviours 1–5 and decisions 2–16 are settled. Multi-asset: every order carries its instrument (System map decision 37).

Order Manager · What this component does

What this component does

Order Manager sits between the slot and the Gateway on the order path.

Sending. StrategyExecution hands it order requests — single orders, or a group of protective orders — and cancels. It stamps each order with its id, account, instrument and slot tag, gives a group's orders one fresh shared group, and sends each to the Gateway exactly once.

Tracking. Strategy forwards it every broker order update. It applies each execution to the owned order's cumulative filled quantity and average price, treats Filled / Cancelled / Rejected as closed statuses, and returns what changed so Strategy books only real changes.

Answering. Strategy and StrategyExecution query it directly: is this order mine, what are my submitted, open and cancelling orders (optionally one group's), is a group closed, how much has an order filled. No answer is relayed through another component.

Four stores

StoreHolds
submitted_ordersSent, not yet acknowledged by the broker.
open_ordersAcknowledged, working, not closed.
cancelling_ordersA cancel was sent for an open order; no answer yet.
closed_ordersClosed, kept for the session.

The lifecycle has two entry points: place_order() and cancel_order(id).

Sample C — component-level group/cancel sample

StepInput
(a)A BUY 1 MKT request, then Submitted and Filled 1 @ P.
(b)A group request with orders STP SELL 1 and LMT SELL 1, then OPEN for both orders.
(c)A cancel request for the group, then broker updates LMT Cancelled (0 filled) and, later, STP Filled 1 (the fill won the race).
(d)A cancel request for the filled entry.

Expected: three orders sent to the Gateway; the two group orders share one fresh group name with OCA type 2 and DAY; one cancel sent per open order; none for the entry.

Passes when right after the cancel request both group orders are reported cancelling — neither open nor closed — and the group is not closed. After LMT Cancelled the group is still not closed. After STP Filled the group is closed, STP reports filled 1, LMT reports filled 0, and nothing is left open or cancelling. (d) returns CANCEL_REJECTED_INTERNALLY and sends nothing.

Fails when the group or one of its orders is reported closed because of the cancel request alone, or after only one order's closed status; a cancelling order is reported open; a cancel is sent for an order that is not open; the two orders carry different group names; or the group name equals any earlier name.

Order Manager · Behaviours

Behaviours

1Submit

Given
An order request from StrategyExecution: MKT, STP or LMT; side; quantity; instrument; optional stop or limit price.
Must
Give it a new order id, stamp the slot's account and slot tag, send it to the Gateway exactly once, and record it as owned.
Invariant
Every order the Gateway receives from this slot is owned by it, and no order id is sent twice.

2Group

Given
A group request of one or more protective orders.
Must
Give every order the same group name, fresh for this group, with OCA type 2 and DAY time in force, and submit each order as in behaviour 1.
Invariant
Orders of one group always share one name; a group name is never reused, even after its group is closed; the name is at most 48 characters whatever the slot name (IBKR refuses longer group names with error 401).

3Track per execution

Given
A broker order update forwarded by Strategy.
Must
For an owned order that is not yet closed:
  • Apply each partial or full execution to its cumulative filled quantity and average price, and return the updated order with this update's fill delta.
  • On Filled, Cancelled or Rejected, close it — from submitted, open or cancelling — keeping any quantity filled before.
  • On CANCEL_REJECTED (the broker refused our cancel), move a cancelling order back to open; its own later closed status closes it.
  • A Cancelled the slot did not request (a broker or OCA cancel) closes an open order directly. The broker's pending-cancel status never reaches Order Manager (Gateway decision 6).
Return nothing for an update that is not owned, arrives after the order is closed, or changes nothing. Apply no policy to rejections or system cancels — they are reported as a closed status like any other. Log a cancel or reject only for the slot that owns the order (every slot sees every update), and tag every log line with the slot's name.
Invariant
A closed status is terminal. An order's filled quantity never decreases and is never counted twice. A cancelling order is never reported open.

4Ownership answer

Given
A question from Strategy or StrategyExecution about an order id, the slot, or a group name.
Must
  • Answer whether the order is owned: on_order_update() returns None for an order the slot does not own, and get_order(id) returns None for one it never sent.
  • Report an owned order's status, filled quantity and average price (closed orders stay queryable for the session).
  • List the slot's or a group's submitted, open and cancelling orders, with their filled quantity.
  • List every order of a group (submitted, open, cancelling or closed), and say whether a group is closed.
Invariant
A group's orders are exactly the owned orders carrying its group name, however they were sent. A group is closed only when every one of its orders is closed.

5Cancel

Given
A cancel request for one order by id, for a group, or for every owned order.
Must
For each order in scope that is open: send one cancel to the Gateway and move it to cancelling. For one order by id that is not open (unknown, submitted, already cancelling or closed): send nothing, change nothing, and return CANCEL_REJECTED_INTERNALLY with a warning log. A group or every-order cancel skips orders that are not open.
Invariant
A cancel request never closes an order; only the broker's closed status does (behaviour 3). A submitted order is never cancelled (decision 14).

"""Skeleton contract for Order Manager (Alchemist v3, draft)."""

from __future__ import annotations

from enum import Enum

from alchemist.instruments import Instrument

OCA_GROUP_MAX_LEN = 48


class OrderState(str, Enum):
    SUBMITTED = "SUBMITTED"; OPEN = "OPEN"; PARTIALLY_FILLED = "PARTIALLY_FILLED"
    CANCELLING = "CANCELLING"; CANCEL_REJECTED = "CANCEL_REJECTED"
    FILLED = "FILLED"; CANCELLED = "CANCELLED"; REJECTED = "REJECTED"

CLOSED = {OrderState.FILLED, OrderState.CANCELLED, OrderState.REJECTED}
CANCEL_REJECTED_INTERNALLY = "CANCEL_REJECTED_INTERNALLY"


class OrderManager:
    def __init__(self, gateway, account_id: str, slot: str): ...

    # Behaviours 1-2
    async def place_order(self, instrument: Instrument, side: str, qty: int,
                          order_type: str, stop_price: float | None = None,
                          limit_price: float | None = None,
                          oca_group: str | None = None) -> dict: ...
    async def place_group(self, orders: list[dict]) -> str:
        """One fresh OCA type 2 DAY group; returns its name."""

    # Behaviour 3
    def on_order_update(self, update: dict) -> dict | None:
        """The changed order with its fill delta, or None."""

    # Behaviour 4
    def get_order(self, order_id: int) -> dict | None: ...
    def get_submitted_orders(self, group: str | None = None) -> list[dict]: ...
    def get_open_orders(self, group: str | None = None) -> list[dict]: ...
    def get_cancelling_orders(self, group: str | None = None) -> list[dict]: ...
    def get_order_group(self, group: str) -> list[dict]: ...
    def is_group_closed(self, group: str) -> bool: ...

    # Behaviour 5
    async def cancel_order(self, order_id: int) -> str | None: ...
    async def cancel_group(self, group: str) -> None: ...
    async def cancel_all(self) -> None: ...

Order Manager · Decisions already made

Decisions already made

2Which sample?

The system golden sample for the market-order path, plus a component-level group/cancel sample.

Rejected: a cancel-vs-fill race sample. The race is about state changes at the StrategyExecution level, not something Order Manager can be tested on alone.

3How does StrategyExecution learn that a group is closed?

It asks Order Manager directly (it already holds it to send orders).

Rejected: StrategyExecution tracking orders itself (a second lifecycle tracker that can disagree with this one).

4Who enforces "exit quantity never exceeds the position"?

Strategy / StrategyExecution.

Rejected: an Order Manager guard. Order Manager sends what it is given.

5How much of the lifecycle is tracked?

Per execution: cumulative filled quantity and average price. Closed only on Filled / Cancelled / Rejected; a closed status keeps the quantity filled before it.

Rejected: closed-status-only tracking (partial fills go unbooked until closed).

6What does Order Manager do when the broker rejects or cancels an order in a group?

Nothing beyond reporting the closed status; the policy belongs to StrategyExecution.

7Do closed orders stay queryable?

Yes, for the session — needed to report a group closed with each order's filled quantity.

8How does Strategy avoid double-booking?

on_order_update returns the changed order with its fill delta, or nothing when the update is ignored (not owned, after closed, no change). Strategy books only what is returned.

9Group order attributes?

One fresh group name per group, never reused; OCA type 2; DAY time in force. The name is the slot name cut to 24 characters, -oca-, and 12 hex characters of a hash of slot, clock and sequence — at most 48 characters for any slot name.

11How do callers see the slot's orders?

Through public getters over the stores — get_submitted_orders(), get_open_orders(), get_cancelling_orders(), each with an optional group.

Rejected: a merged "working orders" answer; callers reading the stores directly.

12What is a group's membership?

Each order's own group name across the stores, so an order that joins a group through place_order (a market exit) counts. A group whose orders are all closed is closed.

Rejected: a separate per-group id list kept by place_group (it misses such orders).

13What does a cancel do to an order?

An open order moves to cancelling (listed by get_cancelling_orders(), not by get_open_orders()), and leaves it on Cancelled, Filled (the fill won the race) or Rejected, or on CANCEL_REJECTED (open again).

Rejected: a cancel-rejected order keeping status CANCEL_REJECTED — it is alive or about to fill, so it is open.

14Which orders can be cancelled?

Open orders only. Anything else is refused with CANCEL_REJECTED_INTERNALLY. Group and every-order cancels skip non-open orders. The shutdown coordinator defers a flatten while an order is in flight; the final flat check stays the backstop.

15The broker's pending-cancel status?

Not a status Order Manager sees: the Gateway drops it, and a cancel is confirmed only by the final Cancelled. A cancel the slot did not request leaves the order open until its Cancelled closes it.

16Do outside callers read the cancelling store?

No. Safety's repair selects slots by submitted or open orders.

Accepted cost: if the socket drops while an order is cancelling and its final status is lost, the order stays cancelling for the session; under the join design (StrategyExecution decision 16) no exit waits on it.

Decisions 1 and 10 are not used; the numbers are kept so references stay valid.
