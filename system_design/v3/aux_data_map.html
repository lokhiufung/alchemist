Aux Data

The engine's second input. It reads daily auxiliary series from outside data sources, decides when a value is good enough for the next session, and tells each strategy that reads one whether it is ready to trade.

v3 draft, 2026-11-07 — proposed, not agreed (System map decision 44). The behaviours carry over the auxiliary and arming rules that the Event Loop map held before (its behaviour 8 and the auxiliary part of behaviour 17). Behaviours 1–6 carry those rules over; behaviours 7–9 are new interface rules.

Change history
  • 2026-11-07 — Page created. Auxiliary sources, arming, rechecks and bar values move here from the Event Loop.
Aux Data · Goal

Goal

Give every strategy that reads an auxiliary series a value it can trust for the session it will trade, before that session opens, and keep that value fresh across day boundaries.

Owns, from the System map:

Reading auxiliary daily series from outside data sources, each through one data-source interface; deciding when a value is settled for its target session; arming and disarming each group of strategies that read them; adding the values to bars; and serving the history frames a cold rebuild needs (System map decision 44).

Aux Data · What this component does

What this component does

One resident task steps every arm group at a fixed interval. The Event Loop calls it once per bar to add values. Strategy calls it when it rebuilds.

JobHow
ReadOne AuxSource per outside source: files in replay, an outside source live, and a backup that counts only when a second source confirms it.
JudgeA value counts only when it is the row the calendar names for the target session, settled on that market's own clock.
ArmStrategies are grouped by the session they arm for. Each group has its own target date, deadline and columns.
RecheckAfter arming, a group rechecks every hour until its open, and adopts a changed value.
AnnotateAdds each bound value to a bar before the Event Loop dispatches it.
Serve framesGives Strategy the history frames a cold rebuild needs.

Aux Data · Behaviours

Behaviours

Each behaviour says what Aux Data is given, what it must do, and what must always stay true.

1One interface per outside source

Given
A registered auxiliary name that a strategy reads.
Must
  • Read it through one AuxSource: from files in replay, from the outside source live.
  • Fill a value missing from the primary source with a backup value only when a second source confirms it.
Invariant
A new feed or backup is one new AuxSource class (System map decision 32).

2A value counts only when settled for its target

Given
A group's target date: the next or current trading date of its arm session.
Must
Accept a value only when it is the row the calendar names for that target, settled on that market's own clock (New York for CME, Frankfurt for Eurex). While no settled row can exist yet, fetch at most once per target when no frame is loaded, and warn once per change in what the source serves.
Invariant
A carried-forward value never arms a group.

3Arm groups are independent

Given
The strategies that read auxiliary names.
Must
Group them by the session they arm for, taken from the exchange profile. Give each group its own target date, its deadline (that session's open) and its column scope (pairs of instrument and name). Step every group concurrently, every 60 s.
Invariant
One group's slow fetch or outage never changes another group's verdict.

4Arm before the open, or sit the session out

Given
A group whose value is settled for its target.
Must
  • Give each member its frames through Strategy first. If seeding raises, log CRITICAL and leave the group unarmed.
  • Then mark the group armed and tell each member it is ready.
  • A group not armed by its open sits that session out: no fetch and no late arm for that target. A process started after the open still arms, because the value existed before the open.
  • When the target date rolls, disarm the group and wait for the next value.
Invariant
No strategy is ready on a value that was not settled, or on frames that did not seed.

5Recheck until the open

Given
An armed group before its open.
Must
Refetch at most once per hour. Adopt a changed value, re-seed the members and warn. A recheck that fails, or no longer serves the target, keeps the armed value. A re-seed that raises disarms the group.
Invariant
A member never trades on frames built from a value that was replaced.

6Replay resolves at once

Given
Replay mode, with a replay date.
Must
Load the files at start, resolve every bound name for the replay date, seed and arm the members. Raise when a value is missing.
Invariant
A replay never runs a day with an auxiliary value silently missing.

7Values on the barproposed · new interface

Given
A completed bar, from the Event Loop, before it is dispatched.
Must
Add each auxiliary name bound on that instrument, with its value for the bar's trading date.
Invariant
Strategies on that instrument all see the same bar object with the same values. An instrument with no bound name gets an unchanged bar.

8Frames for a cold rebuildproposed · new interface

Given
Strategy rebuilding its signal cold while the group is already armed.
Must
Answer frames_for(instrument) with the current history frames, so Strategy re-seeds the new signal.
Invariant
A rebuild never leaves an armed slot on an unseeded calculation.

9Members come from the runtime bookproposed · System map decision 34

Given
Each step of the resident task.
Must
Read the members from the runtime book again. A strategy committed later joins its arm session's group only if that group already covers what it reads; otherwise it gets its own group. A crash of the resident task logs CRITICAL.
Invariant
Aux Data keeps no copy of the strategy list.

"""Skeleton contract for the Aux Data component (Alchemist v3, draft)."""

from __future__ import annotations

from abc import ABC, abstractmethod
from datetime import date
from typing import Any

from alchemist.clock import Clock
from alchemist.instruments import Instrument

AUX_STEP_INTERVAL_S = 60.0        # Behaviour 3
AUX_RECHECK_INTERVAL_S = 3600.0   # Behaviour 5


class AuxSource(ABC):
    """Behaviour 1: one outside source of auxiliary daily series."""
    @abstractmethod
    async def fetch(self, name: str, start: date, end: date) -> Any: ...


AUX_SOURCES: dict[str, type[AuxSource]] = {}


class AuxArmGroup:
    """Behaviours 2-5: arming state for one arm session."""
    arm_session: str
    columns: tuple[tuple[Instrument, str], ...]
    ready: bool
    async def step(self, aux: "AuxProvider") -> None: ...


class AuxProvider:
    """Behaviours 1-9."""
    def __init__(self, sources: list[AuxSource], book, clock: Clock) -> None: ...
    async def start(self) -> None: ...
    async def stop(self) -> None: ...
    def annotate(self, instrument: Instrument, bar: dict) -> None: ...
    def frames_for(self, instrument: Instrument) -> dict: ...

Aux Data · Decisions already made

Decisions already made

1Why is Aux Data its own component?

It has its own outside input (not the broker), its own failure modes (source down, value not settled, provisional value changed, backup not confirmed) and its own clock (arming by each session's open). It touches the rest of the engine at three points only: values on a bar, frames for a rebuild, and ready / not ready. Taking it out narrows the Event Loop to bars, dispatch and broker history.

Rejected: keeping it inside the Event Loop (the widest boundary in the system); moving it behind the Gateway (the Gateway is the broker only, System map decision 7).

proposed · 2026-11-07

2Who tells a strategy it is ready?

Aux Data tells Strategy, with the frames. Strategy seeds the signal and then tells StrategyExecution (Strategy behaviour 4). Aux Data never reaches into the signal or the execution state machine.

proposed · 2026-11-07

3Where does a group's arm session come from?

From the exchange profile of the strategy's instrument (System map decision 31). No code branches on a session or exchange name.
