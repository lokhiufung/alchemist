Aux Data · 1 · Goal and scope

Goal and scope

What it is. Aux Data is the engine's second input, beside the Gateway. Aux Data reads daily auxiliary series (values that are not broker prices) from outside data sources, decides when a value is settled for the session a strategy will trade, and tells each strategy that reads a series whether that strategy may trade. One resident task steps every arm group; the Event Loop calls Aux Data once per bar; Strategy calls Aux Data when Strategy rebuilds a signal.

Why it exists. Some signals read a daily series that an outside source publishes, sometimes late, sometimes provisional, on the clock of a market other than the broker's. The Gateway talks to the broker only (System map decision 7), and the Event Loop must stay narrow (bars, dispatch, broker history). Aux Data owns the outside sources, their failure modes and their arming clock, so that no strategy trades on an auxiliary value that was not settled (System map decision 44).

Goal. Give every strategy that reads an auxiliary series a value the strategy can trust for the session it will trade, before that session opens, and keep that value fresh across day boundaries.

Place in the system

Aux Data keeps the members that the runtime book announces in member events; the Event Loop owns the runtime book (Event Loop feature 11). Aux Data steps on the watch time (System map decision 68).

Feature cards

1One interface per outside sourcesettled · was behaviour 1 · System map decision 32

Need
A strategy reads an auxiliary series by name. The strategy must not know which source serves that name, and a new feed or backup must not change any other code.
Upstream gives
Replay has files. Live has an outside source that can be down or late, and a backup source that can be wrong when used alone.
Algorithm
  1. Pick the source registered for the name: files in replay, the outside source live.
  2. Fill a value missing from the primary source with a backup value only when a second source confirms the backup value.
Parameters
ParameterConfigurable?SupportedDefault
Source per nameConfigurable (registry)file source; confirmed backup source—
Confirmations a backup value needsConfigurable per process (System map decision 58)1 second source1
Invariant
A new feed or backup is one new source class. An unconfirmed backup value is never used.

2A value counts only when settled for its targetsettled · was behaviour 2

Need
A strategy that trades a session needs that session's value, not yesterday's value carried forward and not a provisional value.
Upstream gives
A source serves rows by date. The row for a target date appears at some time after that market's close, on that market's own clock, and can be missing for a while.
Algorithm
  1. Take the group's target date: the next or current trading date of its arm session.
  2. Accept a value only when the row is the one the calendar names for that target, settled on that market's own clock (New York for CME, Frankfurt for Eurex).
  3. While no settled row can exist yet, fetch at most once per target when no frame is loaded, and warn once per change in what the source serves.
Parameters
None.
Invariant
A carried-forward value never arms a group.

3Arm groups are independentsettled · was behaviour 3 · decision 3

Need
Strategies on CME and on Eurex arm for different sessions on different clocks. A Eurex outage must not stop a CME strategy from trading.
Upstream gives
The members from member events (feature 9), the watch time, and each instrument's exchange profile with its sessions.
Algorithm
  1. Group the members by the session they arm for, taken from the exchange profile.
  2. Give each group its own target date, its deadline (that session's open) and its column scope (pairs of instrument and name).
  3. Step every group concurrently, every step interval of watch time.
Parameters
ParameterConfigurable?SupportedDefault
Step intervalConfigurable per process (System map decision 58)60 s60 s
Invariant
One group's slow fetch or outage never changes another group's verdict.

4Arm before the open, or sit the session outsettled · was behaviour 4 · decision 2

Need
Strategy must not mark a slot ready on a value that was not settled, or on frames that did not seed. A value that arrives after the open must not change a session already running.
Upstream gives
A settled value (feature 2) and Strategy's seeding result.
Algorithm
  1. Give each member its frames through Strategy. If seeding raises, log CRITICAL and leave the group unarmed.
  2. Then mark the group armed and tell each member the member is ready.
  3. A group not armed by its open sits that session out: no fetch and no late arm for that target. A process started after the open still arms, because the value existed before the open.
  4. When the target date rolls, disarm the group and wait for the next value.
Parameters
None.
Invariant
No strategy is ready on a value that was not settled, or on frames that did not seed.

5Recheck until the opensettled · was behaviour 5

Need
A source can correct a value after the group armed. The strategy must trade the corrected value if the correction arrives before the open.
Upstream gives
The same source, which can serve a changed row, fail, or stop serving the target.
Algorithm
  1. Refetch at most once per recheck interval while the group is armed and before its open.
  2. Adopt a changed value, re-seed the members and warn.
  3. A recheck that fails, or no longer serves the target, keeps the armed value. A re-seed that raises disarms the group.
Parameters
ParameterConfigurable?SupportedDefault
Recheck intervalConfigurable per process (System map decision 58)1 h1 h
Invariant
A member never trades on frames built from a value that was replaced.

6Replay arms on the tape timechanged 2026-11-11 · was "Replay resolves at once" · System map decision 71

Need
A replay must arm each group by the same rules as live, so a replay result is evidence about live trading (System map decision 46).
Upstream gives
File sources that hold the whole history, and the watch time, which moves with the tape (System map decision 68).
Algorithm
  1. Step on the watch time, like live (feature 3).
  2. When the cold start has added every member, run one step at once, so that a group whose value is present arms before the first bar.
  3. Run no step before the first event sets the watch time.
  4. A missing value leaves the group unarmed; its members sit the session out with the same warning as live (feature 4).
Parameters
None.
Invariant
Replay and live run the same steps. No replay date is passed to Aux Data.

7Values on the barsettled · was behaviour 7

Need
A signal reads auxiliary values together with the bar, and every strategy on one instrument must see the same values.
Upstream gives
The Event Loop passes each completed bar before dispatch (Event Loop feature 2).
Algorithm
  1. Add each auxiliary name bound on the bar's instrument, with its value for the bar's trading date.
  2. Return an instrument with no bound name unchanged.
Parameters
None.
Invariant
Strategies on one instrument all see the same bar object with the same values.

8Frames for a cold rebuildsettled · was behaviour 8

Need
Strategy rebuilds a signal cold while the group is already armed, and the new signal needs the auxiliary frames to seed.
Upstream gives
The frames Aux Data already holds for the armed group.
Algorithm
  1. Answer a frame request for an instrument with the current history frames.
Parameters
None.
Invariant
A rebuild never leaves an armed slot on an unseeded calculation.

9Members come from member eventschanged 2026-11-11 · was "Members come from the runtime book" · System map decision 71

Need
A strategy added while the process runs must get its auxiliary values like any other strategy (Event Loop feature 11). Aux Data must not read the runtime book (System map decision 61).
Upstream gives
A member event from the runtime book each time a strategy joins it (at commit) or leaves it.
Algorithm
  1. Keep the members from the member events: add a strategy when it joins, remove it when it leaves.
  2. A strategy committed later joins its arm session's group only if that group already covers what the strategy reads; otherwise the strategy gets its own group.
  3. A crash of the resident task logs CRITICAL.
Parameters
None.
Invariant
Aux Data holds no reference to the runtime book and no clock. A strategy committed later is a member from its member event.

"""Skeleton contract for the Aux Data component (Alchemist v3)."""

from __future__ import annotations

from abc import ABC, abstractmethod
from datetime import date
from typing import Any

from alchemist.instruments import Instrument

AUX_STEP_INTERVAL_S = 60.0        # Behaviour 3
AUX_RECHECK_INTERVAL_S = 3600.0   # Behaviour 5


class AuxSource(ABC):
    """Behaviour 1: one outside source of auxiliary daily series."""
    @abstractmethod
    async def fetch(self, name: str, start: date, end: date) -> Any: ...


AUX_SOURCES: dict[str, type[AuxSource]] = {}


class AuxArmGroup:
    """Behaviours 2-5: arming state for one arm session."""
    arm_session: str
    columns: tuple[tuple[Instrument, str], ...]
    ready: bool
    async def step(self, aux: "AuxProvider") -> None: ...


class AuxProvider:
    """Behaviours 1-9."""
    def __init__(self, sources: dict[str, AuxSource], watch_time, config) -> None: ...
    def member_joined(self, strategy) -> None: ...
    def member_left(self, name: str) -> None: ...
    async def members_changed(self) -> None: ...
    async def start(self) -> None: ...
    async def stop(self) -> None: ...
    def annotate(self, instrument: Instrument, bar: dict) -> None: ...
    def frames_for(self, instrument: Instrument) -> dict: ...

Decisions already made

1Why is Aux Data its own component?

It has its own outside input (not the broker), its own failure modes (source down, value not settled, provisional value changed, backup not confirmed) and its own clock (arming by each session's open). It touches the rest of the engine at three points only: values on a bar, frames for a rebuild, and ready / not ready. Taking it out narrows the Event Loop to bars, dispatch and broker history.

Rejected: keeping it inside the Event Loop (the widest boundary in the system); moving it behind the Gateway (the Gateway is the broker only, System map decision 7).

decided 2026-11-09 · proposed 2026-11-07

2Who tells a strategy it is ready?

Aux Data tells Strategy, with the frames. Strategy seeds the signal and then tells StrategyExecution (Strategy feature 3). Aux Data never reaches into the signal or the execution state machine.

decided 2026-11-09 · proposed 2026-11-07

3Where does a group's arm session come from?

From the exchange profile of the strategy's instrument (System map decision 31). No code branches on a session or exchange name.

decided 2026-11-09 · proposed 2026-11-07

4Which time does Aux Data read, and where do its members come from?

The watch time, and member events from the runtime book (System map decision 71). In replay the watch time is the tape time, so no replay date is passed in.

Rejected: the watch time with reads of the runtime book (a reach across the boundary, decision 61); keeping the replay date and the one-pass resolve (a replay-only path, decision 46).

decided 2026-11-11
