Glossary · GLOSSARY · Alchemist v3

Glossary

The words this design uses, each with what it means, its name in code and one example. Reuse these words when you write a page, a map or code; add a new one only when no term below already covers the idea.

v3 final, 2026-11-09.

Change history
  • 2026-11-09 — Latency is two measures: processing latency (the 5 ms budget) and feed latency. Aux Data is no longer proposed.
  • 2026-11-09 — New terms: tick update, bar update, quote update (reserved), market-data message type, runner, operator, broker journal. Bar now covers bar updates. Examples no longer use the L-cross run.
  • 2026-11-07 — New Code column: each term names its symbol in the skeleton code. Shared runtime terms added (configuration, strategy key, strat, account, warmup, intraday seed, readiness flags, recorded and deferring bars, fill engine, reserve, staging, deploy fingerprint, recorders, stores, order state). Renamed: Trading day → Trading date, Flush grace → Bar flush grace, Repair → FSM repair.

Terms

Code names are relative to the alchemist package; a bare Class.member means the class named above it in its table.

Markets and money

TermDefinitionCodeExample
Asset classThe kind of product an instrument is: future, stock or option. It decides how the tradable contract is resolved and what one unit of size is.instruments.AssetClassFDAX is a future; 1 unit of a stock is 1 share.
InstrumentA tradable product: asset class, symbol, exchange profile, currency, multiplier, tick size. Every tick, bar, order, fill and position carries one.instruments.InstrumentFDAX on Eurex, EUR.
Exchange profileAll facts about one exchange in one place: sessions, calendar and early closes, data session, contract venue, currency, broker contract identity, futures roll rule, session-end cutoffs.exchange_profiles.ExchangeProfileThe CME profile; the Eurex profile.
SessionA named trading window of an exchange, on that exchange's local clock.ExchangeProfile.sessionsCME day session 09:30–16:00 New York.
Data sessionThe exchange's continuous feed window; the market-data watchdog arms on it whatever the strategies' own sessions are.ExchangeProfile.data_sessionCME: Sunday 18:00 → Friday 17:00 New York, less the daily break.
Trading dateThe date a bar belongs to by its session; an overnight session rolls at its open, not at midnight.ExchangeProfile.trading_dateA Sunday-evening CME bar belongs to Monday.
Contract venueThe exchange a contract is routed to at the broker, from the exchange profile.ExchangeProfile.contract_venueCME for NQ.
Contract rollThe switch from the expiring futures contract to the next, by the exchange profile's roll rule.ExchangeProfile.broker_contractRoll a set number of days before expiry.
Roll mismatch datesSessions where the feed is a newly rolled, still-thin contract.Gateway.roll_mismatch_dates—
Signal / execution instrumentThe instrument a strategy reads / the instrument its orders and position live on. Usually the same. Replaces a ticker pair.Strategy.signal_instrument, Strategy.execution_instrumentRead ES, trade ES.
CurrencyEvery money amount carries one; the engine never converts between them.Instrument.currencyFDAX PnL in EUR, NQ PnL in USD.
AccountThe broker account a slot trades through and attaches to its orders; not the strategy key.StrategyConfig.account_idTwo slots on one product through two accounts.
Auxiliary seriesA daily series from an outside data source (not the broker) that a signal reads.aux_data.AuxSourceA daily index close.
Aux columnOne auxiliary value added to a bar under a registered name.AuxProvider.annotateThe previous index close on each bar.

Engine

TermDefinitionCodeExample
ConfigurationThe loaded deployment config: system settings, one entry per slot, and one typed section per component.config.Configuration, SystemConfig, StrategyConfig—
bot_idThe deployment identifier that namespaces runtime state files.SystemConfig.bot_idPaper and live use different values.
Strategy keyThe configured name of one slot; it namespaces the slot's persisted state and is what a deploy request adds.StrategyConfig.name, Strategy.namemacd_long_nq_1.
stratThe registered name of the strategy class a slot runs; several slots may share one.StrategyConfig.strat, register_strategyTwo slots with the same strat.
SlotOne configured strategy instance: one Strategy with its StrategySignal, StrategyExecution and Order Manager.strategy_builder.strategy.StrategyA strategy key in the deployment config.
Execution blockA slot's optional execution mapping that names its StrategyExecution class and that class's options.StrategyConfig.execution, make_executionA protected execution with a resting stop.
Event bufferThe one shared queue the Event Loop drains: ticks, bars, order updates, balance and position updates, repaired fills, book operations, end of data.event_buffer—
Drain passOne run of the Event Loop over everything in the buffer.EventLoop.run—
Drain wake-upThe signal a producer raises after appending, so a drain pass starts without waiting for a timer.drain_wakeup—
Buffer idleThe event buffer's state after the drain finds both lanes empty, so every event the drain took has been handled. A push clears the state. The replay feed waits for this state before each bar.EventBuffer.idle, wait_idleThe simulated broker sends bar N+1 only after the strategies have handled bar N.
Tick / tick updateOne trade from the feed: timestamp, price and size. The Gateway sends it as a tick_update message.tick_update, Resampler.update_from_tickThe IBKR gateway sends ticks.
Bar updateOne completed OHLCV bar at a stated resolution, sent by a gateway whose broker serves bars (klines). The Event Loop takes it as a completed bar, without the Resampler.bar_updateThe simulated broker sends 1-second bars from its tape.
Quote updateAn order-book change. Reserved; out of scope for v3.quote_update—
Market-data message typeThe message type a gateway declares per instrument: tick_update, or bar_update with its resolution.Gateway.market_data_typeMES on the simulated broker: bar_update, 1 s.
Bar (OHLCV bar)A completed 1-second OHLCV bucket of one instrument, built from ticks by the Resampler or taken from a bar update. Every bar enters dispatch through emit_bar.event_loop.resampler.Resampler—
ResamplerThe tick-to-bar builder; drops late and out-of-order ticks.Resampler—
Clock-driven bar flushA quiet bar forced out by the clock when no tick rolls it over.EventLoop.fire_due_bars, Resampler.flush_due—
Bar flush graceHow long a quiet bar may wait before the clock-driven bar flush (1.0 s).SystemConfig.bar_flush_grace_s—
ClockShared code giving the time: WallClock live, ReplayClock in replay, which moves forward on each bar close.clock.Clock, WallClock, ReplayClockSession-end flatten reads clock.now().
RunModeThe run mode (replay, paper, live), built once by the runner to choose components and stand-ins. No component reads it.run_mode.RunMode—
WarmupSeeding a slot's signal from history before it trades: daily bars, prior-session bars, auxiliary frames.Strategy.warmup, event_loop.seeder.Seeder—
Intraday seedThe prior session's trailing 1-second bars, for calculations with a rolling intraday window.Gateway.get_intraday_seed_bars—
Seed stateOne value per slot: pending, ready, quarantined (recoverable) or quarantined (terminal).seeder.SeedStateA failed prior-session fetch leaves the slot pending until the retry lands.
warmup_ready / aux_ready / ready_to_armThe two readiness flags StrategyExecution holds, and their AND, which lets a slot arm.StrategyExecution.warmup_ready, aux_ready, ready_to_arm—
Recorded barsToday's bars already written to disk, replayed on a mid-session start.BarRecorder, seeder.load_recorded_bars—
Deferring barsHolding a slot's live bars aside while recorded bars replay, then stepping them in order.Strategy.deferring_bars—
TapeThe stored 1-second bars the simulated broker replays and builds history from.simulation_gateway.TapeSourceOne instrument's day-session tape.
Simulated brokerThe Gateway implementation that replays a tape and fills orders, behind the same interface as the real broker.gateways.SimulationGateway—
Match barThe simulated broker's step before it sends a bar: fill resting orders that the bar touches, then make the bar the current bar for market orders.SimulationGateway.match_barA SELL LMT at 5100 fills when the next bar's high reaches 5200.
OrderFillingEngineThe simulated broker's fill pricer: a fill reference on the current bar plus slippage in ticks.OrderFillingEngine, fill_reference, slippage_ticksFill at the bar close, 1 tick worse.
Gateway capabilityAn optional Gateway method declared on the interface with a safe default.Gateway.market_data_ready, …—
Runtime bookThe one registry of strategies the process runs and the per-instrument resources serving them; changed only between events.event_loop.book.RuntimeBook—
ReserveSetting up an instrument's resampler, bar buffer, contract and recording partition before any slot on it is committed.RuntimeBook.reserve_instrument—
Book operation / commit boundaryA change to the runtime book, handed to the drain loop and run between events.enqueue_book_op, RuntimeBook.commitCommit a new strategy.
Hot-add / deploy requestAdding one strategy to a running paper or live process, asked for over the runner's local socket.DeployService, send_deploy_requestdeploy_strategy.py --key KEY.
Staging / candidateA strategy built and prepared by a deploy request but not yet committed.DeployService.stage_strategy, Candidate—
RunnerShared code that builds, starts and stops the components in a fixed order and owns the deploy socket. Not a component.run_strategies.py, runtime.RuntimeRuntime.build(cfg, mode)
Deploy statusOne status line the deploy socket sends back for a deploy request; registered and noop are the successful final statuses.DeployStatuspreparing, registered, rejected.
Refusal reasonWhy a deploy request was rejected before anything was touched.RefusalReasonsession_open, after_process_exit.
OperatorThe person outside the system who sends deploy requests and receives status lines, alerts and CRITICAL logs.——
Broker journalThe simulated broker's record of each order received and each fill sent, one JSON line each, written when replay.journal is set. The golden test compares it byte for byte.replay.journalBUY order, BUY fill, SELL order, SELL fill.
Deploy fingerprintThe startup log line recording the config file's sha256 and the run's identity.runtime.log_deploy_fingerprint—
QuarantineA slot parked in ERROR after repeated failures; it sends no orders while the rest carry on.Strategy.quarantine, release_quarantine3 on_bar errors in a row.
Arming / arm sessionA group of slots becoming ready to trade a session once their auxiliary values for it have landed; the session a group arms for.AuxArmGroup, AuxArmGroup.arm_session—
Aux DataThe eighth component: it owns auxiliary series, arming and aux columns.aux_data.AuxProvider—
SafetyMonitorSafety's watcher of the broker socket and the feed; climbs the recovery ladder.safety.SafetyMonitor—
FreezeDetectorA watchdog thread that detects a stalled event loop and dumps stacks; it does not recover.safety.FreezeDetector—
Gateway controllerRestarts the broker gateway process, only inside a maintenance window.safety.GatewayController—
ShutdownCoordinatorSession-end flatten, shutdown requests and the final flat check before exit.event_loop.shutdown.ShutdownCoordinator—
BarRecorder / TradeRecorderWrite bars per instrument per session day / round trips per slot, in live and paper.event_loop.recorders—
CalcStateStore / RoundTripStoreKeep session-fixed signal values / round trips per strategy key across a restart.stores.CalcStateStore, stores.RoundTripStore—
Slot costTime one strategy spends on one bar.——
Queue waitTime an event waits in the buffer before its drain pass takes it.——
Dispatch latencyTime from a bar's closing event entering the buffer to the last strategy on that instrument being done.——
Processing latencyR3's 5 ms p99 budget: from a message's arrival (recv_ts), or the flush time of a bar the clock closed, to each strategy's final decision on it — an order or cancel handed to the Gateway, or no action.recv_tsClosing tick arrives 10:00:01.002, the strategy's order is handed to the Gateway at 10:00:01.006 → 4 ms.
Feed latencyFrom the broker's timestamp on a message to its arrival in the engine (recv_ts − broker timestamp). Measured and logged, with the broker's timestamp precision; not budgeted.recv_ts—

Signal

TermDefinitionCodeExample
CalculationA registered kernel the signal steps every bar, from bars, params and other calculations; one node of the signal's DAG.calculations.Calculation, register_calcsma, a 5-bar moving average.
SessionFixedCalculationA calculation whose value is fixed for the session and may be restored after a restart.calculations.SessionFixedCalculationToday's opening price.
SignalDagThe Python class a signal is written as: typed params it holds itself, and a build_graph() that adds calculations, expressions, conditions and exits to the DAG. The strategy author writes it under local/strategies/.strategy_builder.signal_dag.SignalDag, register_signal_dagMacdSignalDag
RearmWith rearm_required, entry fires only on the per-day rising edge of the entry logic.SignalParams.rearm_requiredA run of 4 bars with macd_line > macd_signal gives one entry.
Strategy dataPosition data Strategy passes into each signal step: entry price, seconds since entry. Both None while flat.Strategy.strategy_data—
WarmEvery warmup calculation has a value.StrategySignal.is_warm—
Cold rebuildDiscarding the signal and building it afresh, then replaying seed bars; only while flat and idle.Strategy.reset_signal, rebuild_intraday_stateLate auxiliary data arrives.
Exit conditionOne named rule that can end a trade; the exit answer is their OR.evaluate_exit_conditionsstop, target.
Exit levelThe price an exit condition compares the close with.exit_condition_levelThe stop price.
Exit inputs / freeze / releaseValues marked to be held at their entry-bar value for the whole trade; frozen on the entry-decision bar, released when flat.freeze_exit_inputs, release_exit_inputsA stop derived from a calculation at entry.
Signal snapshotA log row of the signal's values every N bars.Strategy.signal_snapshot—

TermDefinitionCodeExample
PhaseThe execution state machine's current state. Outside code never reads it; it asks is_processing_order().strategy_executions.PhaseIN_POSITION_ACTIVITY.
Protected slotA slot whose execution class rests broker-side exit orders after each entry.ProtectedStrategyExecutionStop STP + target LMT.
OCA groupOne-cancels-all: broker orders sharing a group name, where one filling cancels or reduces the rest. Type 2 is used.OrderManager.place_group—
LegOne order of a protective group.—The STP leg.
MaskingNot sending a bar-close market exit for a condition a working leg already covers.——

Daily capThe most round trips a slot may complete in one trading date.SignalParams.max_trades_per_day—
FlattenCancel every order, wait until each is final, then one market order for any remaining position.request_flatten, flatten_wantedSession-end cutoff.
Order stateThe life of one order: SUBMITTED, OPEN, PARTIALLY_FILLED, CANCELLING, CANCEL_REJECTED, FILLED, CANCELLED, REJECTED.managers.OrderState—
Closed statusFilled, Cancelled or Rejected; terminal.order_manager.CLOSED—
CancellingAn open order the slot sent a cancel for, with no answer yet.OrderState.CANCELLING—
