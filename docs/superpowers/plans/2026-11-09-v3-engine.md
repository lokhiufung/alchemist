# Alchemist v3 Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the eight-component v3 execution engine designed in `system_design/v3/` until the golden replay sample, every component-map test, the R3 load test and the R5 hot-add pass.

**Architecture:** One process, one asyncio loop, a broker reader thread and a send thread. Gateway → Event Loop (+ Aux Data) → Strategy → StrategySignal / StrategyExecution → Order Manager → Gateway, with Safety beside. Replay, paper and live differ only in what the runner passes in (simulated broker vs IBKR, `ReplayClock` vs `WallClock`, do-nothing stand-ins).

**Tech Stack:** Python ≥ 3.12, asyncio, uv, pytest + pytest-asyncio, pyyaml, python-dotenv, pyarrow (ParquetTape only), ibapi (IBKR gateway only).

**Spec:** `docs/superpowers/specs/2026-11-09-v3-engine-design.md`. The spec defers to `system_design/v3/SYSTEM_MAP.md` and the eight `*_MAP.md` files. Executors read the spec, then the map named in each task, in full, before the first step.

## How to read a task

- **"Map row X"** means the test row named X in the task's component map (section *Tests*: the sample, *End-to-end scenarios*, or a feature-test table). Its *Given / Input / Parameter cases / Passes when / Fails when* are the assertions. Copy its exact values into the test. Each parameter case is one `pytest.mark.parametrize` case.
- **"Feature N"** means feature card N in the task's component map: its *Algorithm*, *Parameters* (defaults) and *Invariant* are the requirements.
- Signatures not written in a task are the ones in the map's *Skeleton code*. Where the existing file under `alchemist/` differs from the skeleton, the skeleton wins, except module paths, where the map's *Step → code* table wins.
- Every operational number from a feature's *Parameters* table goes in that component's typed config dataclass with the map's default (SYSTEM_MAP decision 58). No module-level constant is read at runtime except numbers a broker or a decision fixes.

## Global Constraints

- `requires-python = ">=3.12"`; run tests with `uv run pytest`.
- Default test run uses no network; IBKR tests carry `@pytest.mark.ibkr_paper` and are deselected by default (`addopts = "-m 'not ibkr_paper and not load'"`).
- No component reads the run mode or checks a collaborator for `None` (decision 46).
- No file outside `alchemist/exchanges.py` branches on an exchange name (decision 31).
- Size is always 1 unit; order types MKT, STP, LMT; TIF DAY; outside RTH allowed; bars 1 s only (decisions 24, 56).
- Replay output is deterministic: no wall clock, no random numbers in replay paths; journal keys sorted, `separators=(",", ":")`, prices with 2 decimals, UTC ISO-8601 with milliseconds.
- Never edit `system_design/`. Never refresh `tests/golden/expected/*` without a commit message that says why.
- No long comments; names carry meaning.
- Commit after each task on branch `v3`, message `feat(<component>): <what>`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **`${VAR}` in config not set** (e.g. `GOLDEN_OUT` missing) → startup fails with a message naming the variable; never an empty path. Test in Task 2.
2. **A strategy folder that fails to import at cold start** (syntax error, missing `strategy.py`) → exit code non-zero, error names the folder and file; no half-built runtime. Test in Task 17.
3. **Replay date with no tape bars** (weekend, holiday, wrong date) → simulated broker refuses at `connect()` with a reason naming the date and session; process exits non-zero instead of waiting forever. Test in Task 8.
4. **SIGTERM / Ctrl-C while a slot holds a position** in paper/live → the runner turns it into the Event Loop's shutdown request, the book is flattened, services stop in reverse, exit code reports not-flat if flatten failed. Test in Task 17.
5. **`log_path` directory does not exist** → created at startup (golden `GOLDEN_OUT` is a fresh temp dir per run). Test in Task 2.
